## Abstract

Computer programmers chain together reusable computational primitives in
different orders to implement different algorithms. Existing language models
execute their layers in one fixed order. **Library of Layers (LoL)** instead
uses a small router to select the next layer from a global library of Transformer
blocks. The library size is a single architectural knob: a small library forces
parameter reuse, while a large library allows sparsity. LoL therefore spans a
continuum containing dense, depth-recurrent, and mixture-of-experts behavior.

The paper reports competitive text-pretraining results against all three
baselines. On synthetic Sudoku and maze data, different routing paths implement
different solution strategies, and forcing a learned route can force a strategy.
On multilingual data, the router learns different paths for different languages
and scripts. On safety data, linear probes of router outputs distinguish safe and
unsafe text. The authors present LoL as a way to make the computation graph
itself a learned and controllable object.

## 1. Introduction

Many algorithms use the same primitives in different orders. A database engine,
for example, can filter, join, sort, and aggregate in task-dependent sequences.
Transformer language models normally keep a fixed layer order, which can require
representing useful computational primitives repeatedly at different depths.

Mixture-of-experts models increase sparsity, while looped models reuse layers.
Dynamic-depth models can skip layers, but these approaches still prescribe the
order in which layers are executed. LoL lets a router select the next complete
Transformer block from one global library. A small library makes reuse likely; a
large library leaves many blocks unused on a given pass.

Routing individual tokens creates an attention-space mismatch: neighboring
positions may form queries and keys using different block parameters. Routing an
entire sequence from its first token preserves causality but cannot adapt after
new context is revealed. LoL addresses both issues with **strided window
attention**. It routes each causal window as a unit, restricts attention to that
window, and shifts the boundaries between routed depths so adjacent windows can
exchange information.

The paper's contributions are:

1. A library of complete Transformer blocks from which the router selects the
   block, making layer order, reuse, and effective depth input-dependent.
2. Experiments showing that routes encode language, safety-related information,
   and algorithmic strategies, and that routes can be forced at inference.
3. Comparisons showing competitive performance across parameter-reuse and sparse
   regimes by changing only library size.

## 2. Related work

LoL combines ideas from several families.

- **Parameter sharing and recurrence.** Universal Transformers, ALBERT, looped
  Transformers, recurrent-depth models, and algorithmic recurrent networks reuse
  blocks across depth. LoL retains a middle recurrent core but permits a
  different block order at every routed depth.
- **Dynamic computation.** LayerSkip, Mixture-of-Depths, and Mixture-of-Recursions
  dynamically skip or repeat computation. They generally keep a fixed order for
  blocks that are executed; LoL changes the order as well.
- **Mixture of experts.** Conventional MoE routes tokens to a subset of FFNs.
  LoL routes windows to complete blocks, including attention and the MLP. The
  same block can be selected at several depths.
- **Dynamic module assemblies.** Mixture-of-Modules is closest in spirit, but
  its top-k construction and weighted attention avoid the attention-space
  mismatch differently and it does not use LoL's top-1 per-window ordering.
- **Shared expert pools and cache sharing.** Global expert pools, shared QKV/KV
  designs, and hybrid attention are related systems directions, but LoL's unit of
  routing is a complete Transformer block.

## 3. Learning the order of a forward pass

### 3.1 The library

The model has three parts:

- A fixed-order **prelude** $P$ with full causal attention.
- A routed **core** of depth $D$.
- A fixed-order **coda** $C$ with full causal attention.

The core stores a library of $L$ complete blocks
$\{E_1,\ldots,E_L\}$. Library size $L$ counts distinct parameterized blocks;
core depth $D$ counts block applications. A routing path is the sequence of
selected block identities. For example, with $L=3$ and $D=3$, the path
$E_1\rightarrow E_3\rightarrow E_1$ reuses $E_1$ and never selects $E_2$.
Different windows in the same sequence can follow different paths.

### 3.2 Routing and causality

At every routed depth, tokens are partitioned into windows. All tokens in one
window select the same block and the same residual weight. Attention is causal
and restricted to that window. The window partition shifts at the next routed
depth, so neighboring windows overlap over successive block applications.

This design prevents a query from comparing against keys produced by unrelated
block parameters while still allowing later windows to use information from
earlier windows. The prelude and coda retain full-sequence causal attention.

#### Strided window attention

Let $W$ be the window size, $S$ the stride between routed depths, and
$\ell\in\{1,\ldots,D\}$ the routed depth. The offset is

$$
\delta_\ell=((\ell-1)S)\bmod W.
$$

Position $i$ belongs to window $I_k$ when

$$
w_i^{(\ell)}=\left\lfloor\frac{i+\delta_\ell}{W}\right\rfloor=k.
$$

For an eight-token sequence with $W=4$ and $S=2$, depth 1 uses windows
$\{0,1,2,3\}$ and $\{4,5,6,7\}$; depth 2 uses $\{0,1\}$,
$\{2,3,4,5\}$, and $\{6,7\}$; depth 3 returns to the first partition.
The boundary shift is fixed by depth and does not depend on the selected expert.

#### The router

Let $s^{(\ell-1)}$ be the hidden state before routed depth $\ell$, and let
$\mu_k$ be the mean hidden state in window $I_k$.

For the first window, the router input combines the first token with a learned
vector specific to the routed depth:

$$
r_0=\frac12\left(e^{(\ell)}+s^{(\ell-1)}_0\right).
$$

For a later window, the router sees only prior windows:

$$
r_k=\frac1k\sum_{j=0}^{k-1}\mu_j,\qquad k>0.
$$

A linear router produces probabilities $a_{k,m}$. The selected expert is

$$
\rho_k=\arg\max_m(a_{k,m}+b_m),
$$

where $b_m$ is a per-expert load-balancing bias used only for selection. The
residual interpolation weight is the original selected probability

$$
\alpha_k=a_{k,\rho_k}.
$$

The block output in the window is

$$
s^{(\ell)}_{I_k}=s^{(\ell-1)}_{I_k}
+\alpha_k\left(E_{\rho_k}(s^{(\ell-1)}_{I_k})-s^{(\ell-1)}_{I_k}\right).
$$

The discrete argmax receives no gradient. The differentiable path through
$\alpha_k$ trains the router. Gaussian noise is added to router logits during
training to encourage exploration. The authors use loss-free load balancing;
there is no auxiliary balancing loss in the reported LoL runs.

### 3.3 Increasing depth during training

The routed depth controls most of LoL's training cost. The authors start with a
shallow core and increase $D$ during training. Early steps are cheaper and let
the router explore its library; the final model has the full target depth.

For the main 1B math experiment, the core grows from depth 1 to depth 8 using a
`1 - sqrt` schedule during the first 75% of training. The remaining 25% runs at
full depth. The 360M experiments use a 16-depth core and the same general
curriculum. Figure 7 compares a growing run with a fixed-depth run and reports
lower early FLOPs with only a small final loss increase.

## 4. Experiments

### 4.1 Routing paths encode and control computation

#### Multilingual text

A 360M LoL model is trained for 10B tokens on an equal mixture of ten languages
from FineWeb-2. For each validation window, the selected expert at every routed
depth is encoded as a one-hot path and projected with PCA. Paths cluster by
language; Latin-script languages are closer to one another. The paper's training
plots show these distinctions emerging gradually.

#### Safety text

The authors train on an equal mixture of sequences labeled safe or unsafe by an
external harmfulness classifier, without exposing those labels to the model.
A ridge regression over per-window router probabilities reaches about 0.92
held-out AUROC; averaging router features across the sequence reaches about
0.95 AUROC. A document-level label-shuffling control is at chance, indicating
that the probe is not merely exploiting a fixed split artifact.

The appendix reports development-set cross-validation values:

| Readout or control | AUROC |
|---|---:|
| Top-1 ridge | 0.8754 |
| Single winning-expert probability | 0.8244 |
| Expert-frequency log-likelihood ratio | 0.8300 |
| Shuffled labels, mean / maximum over 99 permutations | 0.5014 / 0.5231 |

These measurements show information in routing features; they do not establish
that the router is a calibrated safety classifier.

#### Sudoku

The dataset contains five solving strategies. Sequences have the form

```text
Q : <input grid> [Sx] R : <solving steps> A : <final grid> <eos>
```

The strategy description is masked from the ordinary network and visible only
to the router. The model is trained on the solving steps and final grid. At
inference, the authors extract a mode path for each strategy and force both the
selected expert and its mean residual weight. The resulting traces follow the
requested strategy and solve held-out puzzles with nearly 100% accuracy.

The five strategies are:

1. Naked singles: repeated row-major single-candidate sweeps.
2. Hidden singles: scan rows, columns, and boxes for unique candidates.
3. Crosshatching: digit-major box elimination.
4. Propagation: FIFO propagation of newly forced cells.
5. Backtracking: deterministic depth-first search with ascending digits.

#### Mazes

The maze task uses loop-free $8\times8$ mazes with distinct start and goal
cells. Each maze has traces for breadth-first search, depth-first search, A*,
bidirectional search, and dead-end filling. All strategies share output syntax;
they differ in the order in which cells are explored. Forcing the learned mode
path causes the model to produce the requested exploration strategy with nearly
100% accuracy.

### 4.2 Mathematical reasoning at 1B scale

The 1B models have 16 total layers: four prelude layers, an eight-depth routed
core, and four coda layers. They train on Nemotron-CC-Math and
OpenMathInstruct-2 for approximately 90 exaFLOPs (about 20B tokens for the most
efficient model). LoL grows its core for 75% of training.

The reported five-shot results are:

| Model | ARC-E | ARC-C | HellaSwag | PIQA | GSM8K |
|---|---:|---:|---:|---:|---:|
| Random | 25.0 | 25.0 | 25.0 | 50.0 | 0.0 |
| Vanilla | 40.8 ± 1.0 | 28.2 ± 1.3 | 31.4 ± 0.5 | 56.6 ± 1.2 | 29.7 ± 1.3 |
| Vanilla, sliding window | 49.5 ± 1.0 | 28.5 ± 1.3 | 31.3 ± 0.5 | 58.8 ± 1.1 | 27.5 ± 1.2 |
| LoL | 50.3 ± 1.0 | 29.1 ± 1.3 | 31.2 ± 0.5 | 59.7 ± 1.1 | 27.9 ± 1.2 |

The LoL and sliding-window baselines are broadly comparable. The full-attention
vanilla baseline is substantially worse on ARC-Easy in this experiment.

### 4.3 Library size and sparsity

Library size $L$ controls the number of distinct blocks; routed depth $D$ controls
how many block applications are executed.

#### Comparison with looped Transformers

The authors train 360M models on 10B FineWeb tokens and compare LoL against
Huginn-style looped Transformers at matched unique-parameter counts. LoL is
competitive in evaluation loss while allowing arbitrary order and reuse. Larger
variance across seeds is attributed to router initialization and the paths it
explores.

#### Comparison with sparse MoE

For a 3:2 sparsity comparison, the conventional MoE uses three experts per layer
with two active, while LoL uses 24 blocks across 16 routed depths. The MoE
baseline has slightly lower training loss by roughly 0.05 (about 2.75 versus
2.80), but LoL remains competitive and shows depth-specialized expert use.

The reported conclusion is that changing $L$ moves LoL continuously between
parameter reuse and sparse behavior without changing the basic routed-core
interface.

## 5. Discussion

LoL makes layer ordering part of the learned computation. The route can be
read, clustered, or intervened on, and the core can in principle run deeper at
inference than during training for test-time compute scaling.

The paper identifies several open directions: using route features for behavioral
intervention, increasing inference depth, combining routed blocks with test-time
learning, and using heterogeneous libraries with different block sizes or
architectures. The paper also notes that top-1 routers can collapse in some
runs, so router initialization and exploration remain practical concerns.

## Appendix A: architecture and training details

The natural-language 360M models use four prelude layers, a 16-depth core, and
four coda layers. They use RoPE, RMSNorm, SwiGLU, and bias-free attention. The
1B shape follows Llama 3.2-1B. Natural-language experiments use window size
$W=128$, stride $S=64$, and context length 1024. Sudoku uses the same window and
stride; mazes use $W=64$, $S=32$. Attention is document-blocked in all
experiments.

The router uses a loss-free load-balancing bias for selection:

$$
\rho_k=\arg\max_m(a_{k,m}+b_m),
\qquad
\alpha_k=a_{k,\rho_k}.
$$

The selected block's residual interpolation is differentiable through
$\alpha_k$ but not through the discrete expert identity. The model uses
per-routed-depth FiLM after each normalization:

$$
\operatorname{FiLM}_s(x)=\gamma_s\odot\operatorname{Norm}_s(x)+\beta_s,
\qquad s\in\{\mathrm{attn},\mathrm{ffn}\}.
$$

The reported optimizer is PyTorch Muon with `adjust_lr_fn=match_rms_adamw`,
plus AdamW for parameters not handled by Muon. This optimizer detail is part of
the paper's baseline and should not be confused with this project's
AdamATan2 fallback.

### Algorithm 1: LoL forward pass

```text
Require: x in V^n, core depth D, window size W, stride S
         parameters P, {E_m}_{m=1..L}, Router, {e^(ell)}_{ell=1..D}, C

s^(0) <- P(x)                                      # full causal attention
for ell = 1 .. D:
    delta <- ((ell - 1) * S) mod W
    I_k <- { i : floor((i + delta) / W) = k }
           for k = 0 .. K_ell - 1
    mu_k <- mean(s^(ell-1)[I_k]) for every window k

    for k = 0 .. K_ell - 1:
        if k == 0:
            r_k <- 0.5 * (e^(ell) + s^(ell-1)_0)
        else:
            r_k <- (1 / k) * sum(mu_j for j = 0 .. k-1)
        (rho_k, alpha_k) <- Top1(Router(r_k))
        y_k <- E_{rho_k}(s^(ell-1)[I_k])
        s^(ell)[I_k] <- s^(ell-1)[I_k]
                          + alpha_k * (y_k - s^(ell-1)[I_k])

p <- softmax(C(s^(D)))                              # full causal attention
return p
```

The router's first-window input is the first token plus the learned depth vector.
Every later-window input uses only earlier windows, which is the causality
condition that makes per-window routing valid.

## Appendix B: architecture ablations

The paper reports three main ablations.

1. **Growing versus fixed depth.** Growing from depth 1 to the target depth
   saves training FLOPs and has only a minor final loss cost. The released
   implementation uses a deterministic `1 - sqrt` staircase. In the main setup,
   growth occupies 75% of training and the final 25% runs at full depth.
2. **Loss-free versus auxiliary-loss balancing.** Loss-free balancing produces
   lower final cross-entropy in the reported comparison.
3. **Untied versus shared routers.** Sharing router weights across routed depths
   changes final loss little, although the paper's main design permits a
   depth-specific router input vector and depth-specific FiLM parameters.

Fixed full attention, ordinary sliding-window attention, and shifted-window
baselines are also compared. The shifted-window baseline alone does not equal
LoL because it lacks the learned block ordering and top-1 route.

The appendix includes an additional experiment in which the forward depth grows
to 16 but only the final eight recurrent steps backpropagate. This is a
LoL-specific backpropagation optimization and relies on the paper's recurrence
implementation; it is not the same as simply skipping early layers in an
ordinary Transformer.

## Appendix C: additional experimental information

### C.1 Multilingual route evolution

The paper plots PCA projections of route one-hot vectors at checkpoints from 500
to 9,389 steps. Language clusters become more distinct over training, while
Latin-script languages remain closer together.

### C.2 Safety readouts

The safety appendix compares ridge regression, a single winning-expert
probability, an expert-frequency log-likelihood ratio, and document-level label
shuffling. The values are reproduced in the safety table above.

### C.3 Sudoku data

The authors generate Sudoku grids by randomized depth-first filling, retain 30–36
clues, solve each puzzle with all five strategies, deduplicate, and obtain about
20M sequences (approximately 10B tokens). Strategy descriptions are visible to
the router but masked from the rest of the model. The paper reports mode-path
agreement by window and depth, then evaluates forced-path generation using
strategy adherence, legality, rule faithfulness, answer correctness, and the
amount of padding before `<eos>`.

### C.4 Maze data

The authors generate loop-free 8×8 mazes with randomized recursive backtracking,
require a unique trace per strategy, require DFS to backtrack, and require BFS
to expand cells outside the final path. They produce 7.2M mazes and 36M
strategy sequences, approximately 10B tokens. The five strategy formats and
forced-path evaluation mirror Sudoku.

The final appendix figures show expert-utilization heatmaps for the looped-model

## Project research: implications for the H-Net design

This section is an analysis of applying LoL to the current raw-byte H-Net. It is
not a claim that the paper's decoder-only architecture is a drop-in replacement.
The H-Net has a hierarchical byte/chunk interface, heterogeneous SSM and
attention blocks, FP8/TE execution, MSAR, FBT, and a latent MoE path. LoL assumes
that blocks in its routed library have compatible input/output and attention
semantics.

### Features that become redundant in a LoL middle core

| Current feature | Status if LoL replaces the middle core | Why |
|---|---|---|
| Fixed `S3T1` ordering in the middle | **Replaced** | LoL chooses a complete block at each routed depth. The fixed three-SWA/one-FA placement is no longer the execution rule. |
| Explicit `inner_loops=2` over the middle layers | **Usually replaced** | LoL's core depth $D$ already controls repeated block applications, and a selected library block may be reused at multiple depths. A separate two-pass loop would duplicate the same role. |
| Separate active-depth growth controller | **Replaced by LoL growth** | LoL has its own core-depth curriculum. The paper uses a `1 - sqrt` staircase from depth 1 to the target over 75% of training, then a full-depth phase. Do not stack two independent depth schedules without an explicit experiment. |
| Per-layer, token-routed LatentMoE as the main middle routing mechanism | **Replaced at the routing level** | LoL routes complete blocks per causal window. A second token-level router inside every routed depth would be nested routing, not the LoL design. |
| `FusedTokenRouter` for the middle's primary dispatch | **Replaced** | The LoL router is top-1 per window and per routed depth, with causal prior-window inputs and a loss-free selection bias. The dispatch unit is a window/block pair rather than a token/expert pair. |
| Middle-only manual shared-expert overlap | **Not needed for pure LoL routing** | LoL does not have a conventional always-on shared FFN expert in its core. It could be retained inside every library block, but then the design is a nested LoL-plus-MoE hybrid. |
| FA-specific NoPE and FA KV-compression machinery in the routed core | **Likely removed from the pure LoL core** | The paper's routed core uses strided causal windows. Full causal attention is placed in the prelude and coda. Any retained global FA elsewhere still needs its own positional and KV policy. |

### Features that are not automatically obviated

- **Raw byte lifting, learned H-Net chunking, dechunking, and the output head.**
  LoL changes the middle computation order; it does not provide a byte encoder or
  a hierarchical latent interface. The clean hybrid is to route over the latent
  sequence after chunking and before dechunking.
- **Outer S2M3 encoder/decoder and Mamba-3.** The paper's library contains
  compatible Transformer blocks. Keep the outer chunking stacks fixed unless we
  deliberately design a heterogeneous SSM/attention library with compatible
  recurrent state and cache semantics.
- **FBT.** FBT is an outer full-bandwidth training objective. It can call the
  LoL-backed middle twice, but both passes must use an explicitly chosen routing
  policy. Recomputing routes independently changes the objective; reusing routes
  makes the feedback pass deterministic.
- **MSAR.** LoL's residual interpolation is not the same as MSAR's multi-scale
  residual history. The current layer-indexed MSAR parameters cannot be reused
  unchanged if a block can execute at arbitrary routed depths. MSAR can remain in
  the outer boundary or be redesigned with routed-depth state, but it is not
  automatically replaced by LoL.
- **LeRoPE/RoPE.** Positional information is still needed inside local causal
  windows. LeRoPE can be used in a compatible library. The current NoPE decision
  is specific to global FA and would need reconsideration if global FA is removed.
- **Muon/GramNS, AdamATan2 fallback, decay, FP8/TE, fused kernels, DDP, and
  CUDA graphs.** LoL does not replace optimization or systems infrastructure.
  It makes graph capture and DDP harder because the selected block set changes;
  window counts, capacity, dispatch buffers, and used-parameter behavior must be
  static or handled with stage-specific recapture.
- **Document-aware packing and boundary reset masks.** The router may use only
  causally available windows, and documents must not leak into one another. The
  H-Net document masks remain necessary.

### The key architectural choice

A conservative integration would apply LoL only to the deepest latent middle
stack. Use a library of compatible middle blocks, keep the byte/chunk encoder and
decoder fixed, and preserve the H-Net outer S2M3 path. In that design, the
features actually removed from the middle are the fixed block order, explicit
inner loop, fixed middle depth schedule, and primary per-token MoE router. The
remaining H-Net features are retained because they solve different problems.

A full heterogeneous LoL library containing Mamba-3, SWA, and FA blocks is a
separate architecture. It needs a state/cache contract for selecting different
SSM and attention blocks at different windows and depths, and it cannot claim the
paper's implementation or throughput without new evidence.
